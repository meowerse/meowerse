# Audit: meowsenger-web (M-xx)

- **Date:** 2026-09-24
- **Scope:** `apps/meowsenger-web` (Astro + React islands), plus the parts of `workers/meowsenger` (BFF, `Conversation` and `UserInbox` Durable Objects, OIDC) that the UI depends on. Live site: https://meowsenger.alxnko.dev.
- **Mode:** read-only. No code was changed. Evidence comes from:
  - reading the code (all paths below are relative to the repo root);
  - 9 probe tests run against a scratch copy of the app;
  - a local build;
  - headless-Chrome screenshots of the signed-in UI against a mock backend;
  - read-only `curl` requests to the live site.
- **Decisions this answers:** B7 (find existing issues), B8 and B10 (terminal styling and cohesion), B9 (no blocking background logic). Guidelines are cited by their ui-ux-pro-max rule id, e.g. `loading-states`.

## Findings

Severity:
- **blocker:** loses or corrupts user data, or silently breaks the core action.
- **high:** a core flow is wrong or unreachable for a common case.
- **medium:** a real defect with a workaround.
- **low:** polish.

## Terminal-styling recommendations (B8, B10)

### Verdict

**Adopt the `›` prompt composer with constraints.** It helps as long as the `›` is decoration on an ordinary, clearly boxed field. It hurts if it turns the field into a borderless command line.

**Why it helps:**
- It is the one place where the brand's tty voice has a natural meaning ("type here").
- It costs nothing in discoverability when the placeholder, the box and the send button stay.
- With JetBrains Mono everywhere, the glyph shares metrics with the text, so it sits on the baseline without tricks.

**Why it could hurt:**
- **Discoverability:** a bare `›` with no box and no send button reads as developer UI to non-technical users.
- **IME and multiline:** a "command line" implies Enter executes, which conflicts with Shift+Enter, phone newlines and IME composition (M-17, M-18).
- **Accessibility:** a fake block cursor or blinking caret competes with the native caret, and a glyph-only affordance has no name.

### Exact recommendation for the composer

1. **Structure.** Use `<div class="prompt">` containing a `›` span (`aria-hidden="true"`) and a real `<textarea>` with a visible (or `sr-only`) `<label>` "message". Next to it goes a real `<button>` "send" with an icon plus an sr-only label. It is never a contenteditable and never a custom caret.
2. **Geometry (tokens from spec §2.1).** Size the prompt exactly like a `Field` (§7.1.3):
   - **Box:** `min-height: 44px` (the target minimum); 1 px `line` border, `lineStrong` on hover, `focus` ring on focus-within; `radius: m (4px)`; `padding: 12px 12px 12px 32px` so the text starts after the glyph.
   - **Glyph:** at `left: 12px`, 16 px, `line-height` equal to the textarea's (24 px). Top-aligned to the **first line** (`top: 10px`), not vertically centred, so it stays beside line 1 as the field grows. It is `fgSubtle` at rest and `accent` on focus. That is the region's single tty accent (§7.1.5).
   - **Text:** 16 px on phones (to avoid iOS zoom) and 14 or 16 px on desktop, line-height 1.5. Auto-grows to 6 lines (≈ 156 px), then scrolls.
   - **Send button:** `44×44`, the same `radius: m 4px` and 1 px border as the field so the pair reads as one control. `accentFill` background with an `onAccent` icon; it is the screen's one green button (§2.1).
   - **Row:** `display:flex; gap: 8px; align-items:flex-end`, so the button stays level with the **last** line as the field grows. The composer bar has `padding: 8px 12px` plus `env(safe-area-inset-bottom)` (M-19), on a `bgElev` surface with a 1 px `line` top border.
   - **Disabled state:** never disable the textarea (M-05). The send button uses the shared disabled opacity plus a reason (§7.1.4).
3. **Behaviour.**
   - Placeholder: `message` (spec §7).
   - Desktop: Enter sends, Shift+Enter adds a newline, and the hint "enter ↵ send · shift+enter newline" shows as 12 px `fgSubtle` helper text on first use only.
   - Phones: `enterkeyhint="enter"`, Enter adds a newline, and the button sends.
   - Guard every Enter with `isComposing` (M-17).
   - While offline: queue the message and show a pending glyph on the bubble (M-03).
4. **Sitting next to bubbles, avatars and the sidebar.** The aim is one family, not a terminal glued onto a chat app.
   - **Bubbles:** `radius: l 8px`, with the corner nearest the sender at `s 2px` (the "tail") rather than the current 14/7 px. That keeps them clearly "chat" while sharing the 2/4/8 scale with the 4 px prompt and buttons.
     - Padding `8px 12px`.
     - Other people's bubbles: `surface` with a 1 px `line` border.
     - Own bubbles: `accent` mixed about 14% into `surface`, with `fg` text. Never green text in light mode (§2.1). Links in own bubbles use `fg` with an underline (M-36).
     - Meta: 12 px `fgSubtle` with tabular numbers, bottom-right.
     - Max width `min(62ch, 85%)`. Mono text runs about 15% wider than the current Outfit, so keep 62ch rather than 70ch.
     - Use `overflow-wrap:anywhere` for URLs, not `word-break`.
   - **Avatars:** use rounded squares, `radius: m 4px`, 28 px in the log and 40 px in the sidebar, instead of circles. Circles are the only non-2/4/8 shape left on screen, and squares echo the prompt box. The presence indicator is a small 8 px square `accentFill` badge **plus** the text "online" in the header (no colour-only states).
   - **Sidebar:**
     - Rows 64 px: avatar 40, name 14/700 `fg`, preview 13 `fgMuted` (case preserved, M-14), time 12 `fgSubtle`.
     - The active row gets `surface` plus a 2 px `accent` bar on the left. That's an app idiom that also reads as a tty selection, and it is the sidebar's only accent.
     - Put the `meowsenger_` VT323 wordmark in the sidebar header. Don't add `›` to rows or to the search field. The search is a normal `Field` with a search icon.
   - **Header:**
     - The peer's name is 16/700.
     - The sub-line is presence text ("online" / "last seen 5m ago") or "typing…".
     - Connection state is the `StatusLine` (`[wait] reconnecting…`) at the right, **only while it isn't ok** (M-33). That's one tty accent in the header.
     - Actions are ordinary 44 px icon buttons.
5. **Avoid:**
   - a borderless "just a line with `›`" input;
   - `$` or `>` prompts;
   - a blinking block cursor in the field (keep that only on the wordmark);
   - `[send]` text-bracket buttons;
   - a black "terminal panel" behind the composer;
   - CRT or scanline effects;
   - uppercase;
   - monospace-only affordances (e.g. showing Enter as `^M`);
   - more than one tty accent per region (e.g. not both a `›` and an `[ ok ]` inside the composer).
