# Audit: apps/auth-web (auth.alxnko.dev), 2026-09-24

This is a read-only audit for brand v2, requested in decisions B7 and B9. It covers `apps/auth-web`, the `packages/ui`
pieces it uses (`useSession`, `AuthGate`, `Modal`, `ConfirmDialog`, `Field`, `Toast`, `AppHeader`, tokens), and the
parts of `workers/auth` the UI depends on. No code was changed.

**How it was checked**
- **Code:** a line-by-line read of every file in `apps/auth-web/src`, plus the related `packages/ui` and
  `workers/auth/src/index.ts` code.
- **Live site:** read-only GETs and headers (`curl -sI`). Playwright with Chrome took screenshots of 13 public
  pages in 4 variants each: phone 390×844 and desktop 1440×900, light and dark (52 shots). No sign-in, sign-up or
  form submission was done on the live site.
- **Local run:** a build of this worktree, configured with Cloudflare's public test site key and served on
  127.0.0.1:4340. Every API call and the Turnstile script were mocked with Playwright routes. This made it possible
  to drive the signed-in and failure paths (scenarios S1 to S16).
- **Performance:** a local `astro build`, plus a live run under Chrome DevTools throttling (4× CPU, 150 ms latency,
  1.6 Mbps).
- **Guidelines:** findings cite the ui-ux-pro-max rules, e.g. `loading-buttons`, `error-recovery`,
  `timeout-feedback`, `focus-appearance`, `accessible-authentication`.

**Evidence** (all under `/var/tmp/brand-v2-audit/auth-web/`)
- `shots/`: `<viewport>-<scheme>-<path>.png` for the live pages, and `dyn-S*.png` for the local scenarios;
- `dyn-results.txt`: scenario output;
- `live-report.json`: per-page metrics and console errors;
- `headers.txt`, `perf.txt`;
- scripts: `live.cjs`, `dyn.cjs`, `dyn2.cjs`, `perf.cjs`.

The live deploy uses the same hashed assets as this worktree's build (`diff` of `_astro/*` references:
`SAME_ASSETS`). The findings therefore apply to production.

## Findings

Severity:
- **blocker:** a core task fails for most users;
- **high:** a core task can fail or mislead, or there is a real a11y or security gap;
- **medium:** clear friction, or a correctness gap in a secondary flow;
- **low:** polish.

## Redesign notes (tty style, app-shaped)

- **Readiness is visible and part of the terminal voice.** Every async dependency gets a status line under its
  action, e.g. `› checking you're human… ok`, `› checking session…`, `› waiting for telegram (4:12 left) [cancel]`.
  A primary button is enabled only when its dependencies are `ok`. Otherwise it is disabled and the line gives the
  reason and a retry. This covers A-01, A-02, A-11 and A-12, and fits B8/B9.
- **One request layer, and state machines instead of booleans.** `idle | pending | success | error(code, retry)`
  for each action, with timeouts. The `navigating` state never resets. A shared `useAction()` in `@meowerse/ui` would
  close A-03 to A-10 in one place.
- **No global lowercase on user data.** Lowercase belongs in the copy you write (the tty voice), not in
  `text-transform` on `body`. Usernames, app names, codes, error details and titles render as stored, in JetBrains
  Mono. This fixes A-18's delete lockout and keeps proper nouns readable.
- **Forms:** use real `<form>`s with labels above 16 px mono inputs and ≥3:1 borders. The prompt glyph (`›`) is only
  decoration. Put inline field errors in `aria-describedby`, and an error summary on failed submit. Toasts are only for
  successes. Keep password reveal, `autocomplete`, `name`, `autocapitalize="none"` on identifiers, and `enterkeyhint`.
- **Focus and contrast:** there is one green accent. In the light theme, use the dark-green token for focus rings and
  link text, and keep `#00ff82` for fills and dark mode. Check every token pair with a contrast script in CI.
- **Consent is a security screen, not decoration.** Show the app, where it will redirect (host), and a
  first-party/verified mark. List scopes in plain language as checkbox rows ≥44 px tall. Put `allow` and `deny`
  side by side at equal size, with `deny` never hidden.
- **Header:** render guest links in SSR. The signed-in user menu includes sign out. Mark the current page. The mobile
  menu closes on Escape. Only static pages avoid React entirely (A-39).
- **Destructive actions:** follow spec §6 tiers exactly (rotation needs a confirm), and use the native
  `<dialog>`, which makes the page behind it inert (A-20). The confirm phrase is shown in a case-preserving code
  style.
- **Recovery codes** get their own step: a mono grid, download .txt, copy with a "copied" state, an "i saved them"
  checkbox, and no other choices on screen.
- **Cat mascot on sign-in (B4)** must never delay the form. Lazy-load it after the form is interactive, and use a
  static image under `prefers-reduced-motion`. It must not become another island that blocks hydration or causes CLS.
- **Errors page:** render worker authorize errors in the same shell, with a plain cause, "what you can do", and a
  way home (A-28).
